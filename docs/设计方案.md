## 1. 项目概述

### 1.1 一句话定义

一个在浏览器中运行的三维数字孪生运营大屏，用公开无注记底图 + 自建园区白模 + 模拟业务数据，完整演示「发现告警 → 三维定位 → 调派资源 → 路径规划 → 处置闭环」的全过程。

### 1.2 项目目标

- 作为求职作品集，匹配 WebGIS / 三维可视化 / 数字孪生前端岗位
- 证明四类能力：三维场景搭建、业务闭环设计、2D/3D 多视图联动、性能优化与 Shader
- 能在 3 分钟内完整演示，不依赖现场调试
- 代码结构清晰、可在本地运行、可讲解

### 1.3 非目标

- 不做真实生产系统，不接入真实 IoT、视频流、调度算法
- 不做后台管理系统、用户权限、数据库 CRUD
- 不做移动端兼容（仅提示使用 PC）
- 不做全市 / 全省高精度实景三维
- 不做游戏、影视级视觉特效
- 不做任何部署（仅本地运行）

## 2. 命名与文案规范

### 2.1 命名

- 平台名：**云屿园区数字孪生运营平台**
- 场景名：**云屿园区**（虚构，占地约 3 km²）
- 英文标识：`Yunyu Park Digital Twin`

### 2.2 页面上不体现真实地域

- 页面标题、面板、图例、弹窗中**不得出现“青岛”“崂山”“西海岸”等真实地名**
- 层级统一使用：**片区 → 园区 → 楼栋 → 设备**
- 底图必须使用**无地名注记**的影像或深色矢量底图，避免地图自带真实城市名
- 页面底部统一标注：`演示数据 · 公开地理数据 + 自建白模 + 模拟业务数据`

### 2.3 数据与地域的关系

- 几何数据可以使用公开坐标作为空间底数据，不依赖 OSM 轮廓加工
- 不在界面、文档截图、演示视频中出现真实地名
- 面试口径统一为：公开地理数据 + 自建白模 + 模拟业务数据，不声称是真实生产系统

## 3. 最终形态

### 3.1 访问形态

- 仅在本地运行 `npm run dev`，通过浏览器访问，无需登录
- 不做构建产物交付，不做任何部署
- 设计基准 1920×1080，适配 2K / 4K 大屏
- 仅支持桌面端浏览器
- 移动端访问只显示「请使用 PC 端访问」提示

### 3.2 三种使用模式

| 模式 | 使用者 | 用途 |

| 总览模式 | 园区值班员 | 日常巡检、查看设备与告警 |

| 漫游模式 | 领导 / 面试官 | 一键自动巡检讲解，3 分钟看完亮点 |

### 3.3 最终效果关键词

- 深色科技风、玻璃拟态面板、青色描边
- 城市与园区白模、夜间窗光、告警脉冲、边界流光
- 相机缓动飞行、数字滚动、图表入场
- 一键漫游、完整处置时间线

## 5. 使用流程

### 场景 1：日常巡检

1. 打开页面，3 秒加载进度，进入园区全景，相机缓慢自转
2. 左侧概览数字滚动到位：128 栋建筑、200 台设备、98.6% 在线率
3. 点击左侧「3 号楼」，相机飞至该楼，建筑高亮，右侧弹出信息卡（楼层、面积、设备数、告警数）
4. 勾选「设备」图层，设备点位浮现，绿 / 黄 / 红表示状态
5. 点击某台水泵，显示详情卡与温度 / 电流实时曲线

### 场景 2：告警处置（核心演示）

1. 模拟推送：14:31 三号楼 2F 烟感报警
2. 顶部告警条闪烁，右侧告警列表置顶，三维场景出现红色脉冲点
3. 点击「定位」，相机飞至事发楼栋，楼体变红，周边 500m 资源高亮
4. 右侧列出消防站 2.1km、医疗点 1.4km、应急队 0.8km
5. 点击「路径规划」，地面生成路径线并播放车辆行进动画
6. 点击「调派」，左下处置时间线追加：接警 → 调派 → 到场 → 完成
7. 处置完成，告警转绿并归档

### 场景 3：一键漫游（面试演示）

1. 按 `R` 或点击「演示」，进入自动漫游
2. 相机依次飞过：片区全景 → 园区入口 → 3 号楼 → 消防站
3. 每到一处，左侧面板切换讲解数据，右侧图表同步变化
4. 按 `Esc` 退出，回到总览

## 9. 技术架构

### 9.1 架构图

```
数据层   公开无注记底图 / 自建园区 GeoJSON / 模拟业务数据
           ↓  Node 脚本切片与压缩
         GeoJSON / 3DTiles / GLB / KTX2
           ↓
服务层   本地静态资源 + Mock WebSocket 服务
           ↓
渲染层   Cesium（唯一三维引擎 + CustomShader） + Leaflet 小地图 + ECharts 5
           ↓
应用层   Vue3 + TypeScript + Pinia + 大屏布局组件
```

### 9.2 技术选型

| 层级 | 选型 | 说明 |
|---|---|---|
| 框架 | Vue3 + TypeScript + Vite | 主流前端栈，岗位匹配度高 |
| 状态管理 | Pinia | 场景状态、图层状态、告警状态 |
| 三维主场景 | CesiumJS | 唯一三维引擎：场景、白模、3DTiles、相机 |
| Shader / 后期 | Cesium CustomShader + PostProcessStage | 建筑扫描、边界流光、告警扩散、热力 |
| 2D 小地图 | Leaflet | 与 Cesium 双向联动 |
| 图表 | ECharts 5 | 告警趋势、设备状态、能耗 |
| 实时数据 | Node `ws` / 浏览器定时器 | 模拟 WebSocket 推送 |
| 样式 | SCSS + CSS 变量 | 大屏主题与缩放 |
| 运行方式 | Vite dev server | 仅本地 `npm run dev`，不构建、不部署 |

## 15. 风险控制

所有已识别的技术与数据风险，均通过缩减业务与数据规模提前规避。

| 原风险 | 规避方式 | 状态 |
|---|---|---|
| 区域过大、白模过多导致性能不足 | 仅 128 栋自建建筑；周边只加载 1km 内置白模；3DTiles 控制在 30–50MB | 已消除 |
| 建筑高度字段缺失、白模失真 | 使用自建 GeoJSON，高度随数据一并定义，不依赖 OSM 加工 | 已消除 |
| 底图注记暴露真实地域 | 固定使用无注记深色底图 | 已消除 |
| 多引擎坐标错位 | 只使用 Cesium 单引擎，不引入 Three.js | 已消除 |
| 业务数据复杂、口径难统一 | 只保留设备、告警、轨迹三类，全部前端模拟 | 已消除 |
| 数据体积大、仓库臃肿 | 大文件不入库；3DTiles 30–50MB；模型 Draco / KTX2 压缩 | 已消除 |
| 范围膨胀、进度失控 | 锁定 P0 / P1；未列出的一律不做 | 已控制 |

**遗留风险**：无。

**待定项**：无。所有未在 P0 / P1 中列出的功能一律不做。

### 16.2 执行原则

1. **数据先行**：Step 1 的园区数据、建筑 ID、设备与告警映射是后续所有交互的基础，先定 schema 再写业务。
2. **每步可运行**：每个 Step 结束都必须能启动、能截图、能演示，中途停止也有阶段成果。
3. **先闭环后炫技**：先完成 Step 3 的告警处置闭环，再做 Step 4 的 Shader 与性能优化。
4. **不扩容**：任何新想法先对照 P0 / P1，不在清单内的一律不做。
5. **性能实测**：Step 4 的帧率、draw call、加载时间必须记录真实测量值，不使用估算数据。

### 16.4 降级方案

- 若 Step 1 的 3DTiles 切片受阻，立即降级为 Cesium 多边形拉伸 + 内置楼宇，不阻塞 Step 2。
- 若 Step 4 的性能优化未达标，优先保证 1080p 演示流畅，4K 指标降级为“可运行”。
