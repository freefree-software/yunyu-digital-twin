# 部署说明（云屿园区数字孪生运营平台）

## 结论先行

- **最省事**：Cloudflare Pages「直接上传（拖拽 dist）」，零构建配置、免费、无需备案，国内大部分地区可访问，适合对外演示链接。
- **临时现场演示**：`cloudflared tunnel` 把本地 `npm run preview` 暴露成公网 https 链接，5 分钟搞定，适合面试当天用一次。
- **长期作品展示**：GitHub Pages + Actions 自动部署，但需要把 vite `base` 改为仓库子路径，并修一处数据路径硬编码。
- **国内正式环境**：没有真正的零成本方案，免费托管均需境外节点；国内访问稳定必须「备案域名 + 国内服务器/对象存储」，本项目 17MB 产物用任意对象存储 + CDN 即可，但涉及备案成本，不建议为演示投入。

## 前置改动（已完成）

`package.json` 原本没有 `build` 脚本，已补充两条（未改任何业务代码）：

```json
"build": "vue-tsc --noEmit && vite build",
"preview": "vite preview"
```

## 构建与产物

```bash
npm run build      # 类型检查 + 打包，本机实测约 3.5~3.8s 通过
npm run preview    # 本地预览 dist，默认 http://localhost:4173
```

产物实测数据（2026-11-01 本机构建）：

| 指标 | 数值 |
| --- | --- |
| `dist/` 总大小 | 约 17 MB |
| `dist/cesium/`（Cesium 静态资源） | 约 15 MB（占 88%） |
| `dist/assets/`（业务代码 + 样式） | 约 1.4 MB |
| `dist/data/`（园区数据，已正确包含） | 约 456 KB |

最大单文件 6.1 MB，远低于 Cloudflare Pages 的 25 MiB 单文件限制和 GitHub 的 100 MB 限制，各平台均可直接部署。项目未使用 vue-router，是纯单页，**不存在 history 路由回退 404 问题**，所有静态托管开箱即用。

## 各方案操作步骤

### 1. Cloudflare Pages（推荐）

```bash
npm run build
# 打开 https://dash.cloudflare.com → Workers & Pages → Create → Pages → Upload assets
# 把 dist 文件夹拖进去，得到 https://<项目名>.pages.dev 链接
```

### 2. GitHub Pages（需注意 base 路径）

Pages 地址为 `https://<用户>.github.io/<仓库>/`，属于子路径托管，必须改两处（当前**未改**，上线前再做）：

```ts
// vite.config.ts 增加：
export default defineConfig({
  base: '/<仓库名>/',   // 例如 '/yunyu-digital-twin/'
  // vite-plugin-cesium 会自动把 Cesium 资源拼到该 base 下，无需额外配置
})
```

```ts
// src/data/campus.ts 第 3 行，硬编码的 '/data' 改为跟随 base：
const DATA_ROOT = `${import.meta.env.BASE_URL}data`
```

然后用 Actions 自动部署（或本地 `npm run build` 后把 `dist` 推到 `gh-pages` 分支）。

### 3. Netlify / Vercel

两者都支持拖拽 `dist` 或连接 Git 仓库自动构建，构建命令填 `npm run build`，输出目录填 `dist`。免费档够用，但国内访问稳定性不如 Cloudflare。

### 4. 临时隧道（面试现场）

```bash
npm run preview -- --port 4173 &   # 先本地起产物
npx cloudflared tunnel --url http://localhost:4173
# 终端会打印一个 https://xxx.trycloudflare.com 临时域名，直接发给面试官
```

依赖本机开机和网络，域名每次重启变化，只适合一次性演示。

## 常见踩坑

1. **base 路径白屏**：`dist/index.html` 里资源默认以绝对 `/` 引用，子路径托管（如 GitHub Pages）不改 `base` 会全部 404 白屏。
2. **Cesium 资源 404**：`vite-plugin-cesium` 会读取 vite 的 `base` 并自动拼接 `CESIUM_BASE_URL`，只要 base 设对，Workers/Assets/Widgets 不会 404；手工搬运 dist 时注意不要漏拷 `cesium/` 目录。
3. **数据 404**：`src/data/campus.ts` 中 `DATA_ROOT = '/data'` 是硬编码绝对路径，子路径部署必须按上文改为 `import.meta.env.BASE_URL` 形式；`dist/data` 已确认随构建正确输出。
4. **HTTPS / 跨域**：Cesium 默认底图走 Cesium Ion 需联网且要求 https 环境（隧道和 Pages 均自带 https，无问题）；国内访问 Ion 可能慢，演示前建议先打开页面预热。
5. **国内打不开**：海外免费托管在国内均无 SLA 保证。若面试官网络打不开，立刻降级到隧道方案或本地 `npm run preview` 投屏。

## 如果只是面试演示

1. 平时维护：只保留 Cloudflare Pages 一条链接，每次改完 `npm run build` 重新拖一次 dist，30 秒更新。
2. 面试当天：本地 `npm run preview` + `cloudflared tunnel` 双保险；再准备一段本地录屏兜底。
3. 不要做：备案买服务器、配自定义域名、接 CI——对本项目（纯静态、无后端、无路由）都是过度投入。
